# 실제 PPT 제작·편집과 검토

`.pptx` 제작·파일 검토를 할 때 읽는다. 내용·과학적 의미는 `research-presentation`이 관리하고 파일 제작·렌더링은 별도 `slides`의 지침과 도구를 사용한다.

## 작업 환경과 입력 보존

1. 설치된 `slides/SKILL.md`와 필요한 도움말을 읽고 실행 환경을 확인한다. 스킬 설치만으로 제작 의존성까지 설치된 것은 아니다.
2. 별도 작업 디렉터리에서 새 파일이나 입력 사본을 다룬다. symlink·절대 출력 경로가 원본에 연결되지 않는지 확인한다. 연구 데이터·기존 발표·검증된 그림은 보존한다.
3. Python·Node, `pptxgenjs`, helper의 실제 import, LibreOffice·Poppler·글꼴을 확인한다. 누락된 패키지는 작업 전용 venv와 npm 디렉터리에 설치하고 버전을 기록한다. 전역 환경·셸 설정을 바꾸지 않는다.
4. helper는 작업 공간으로 복사한다. 모듈 검색은 그 작업 공간의 Node 환경을 기준으로 한다. `skia-canvas` 등 네이티브 의존성 실패는 원인·필요 환경을 밝히고 다른 제작 경로로 몰래 전환하지 않는다.

설치 시 확인한 환경·의존성·실제 검증 범위는 [검증 기록](validation.md)에 있다. 재생성할 작업에는 검증한 패키지 버전·lockfile을 남긴다.

## 제작

- 새 발표는 PptxGenJS로 만들고 `.js`와 입력 자산을 남긴다. 기본은 `LAYOUT_WIDE` 16:9이며 원본 편집은 기존 비율·스타일·범위를 유지한다.
- 텍스트·단순 도형·차트는 가능한 한 편집 가능하게 만든다. 검증된 과학 그림은 재작성할 이유가 없으면 보존한다. 밴드·등고선 등에는 표준 플로팅 도구의 SVG/PNG를 사용한다. 원본 수치를 바꾸거나 데이터 없는 곡선을 그리지 않는다.
- 기존 파일 수정은 먼저 렌더링과 구조를 확인한다. 전체 재작성으로 노트·마스터·도형·인용·애니메이션을 잃을 수 있으면 독립 사본에서 보존 가능한 방법을 택하고 제한을 보고한다.
- 이미지 종횡비를 유지하고 축·범례·조건을 제거하는 crop을 피한다. 수식·개념도와 실제 결과를 구분한다.
- SVG 수식도 실제 대상 렌더에서 누락·깨짐이 있을 수 있다. 문제가 확인되면 원본 SVG·LaTeX를 보존하고 표준 rasterizer로 만든 고해상도 PNG를 병행할 수 있다. 수식·데이터를 생성형 이미지로 대신하지 않는다.
- 한글 지원 설치 글꼴을 지정하고 실제 렌더에서 한글·그리스 문자·첨자·음수 부호를 확인한다. fontconfig에서 찾은 글꼴도 Matplotlib에서는 미등록일 수 있으므로 그림 생성기의 글꼴 인식·누락 경고를 별도로 확인한다. 다른 컴퓨터의 글꼴 차이에 대비해 PDF를 함께 제공한다.
- 노트는 슬라이드 노트 영역에 넣는다. 노트 작성이 실제 리허설 완료를 뜻하지 않는다.
- 출력 이름·디렉터리는 작업별로 구분한다. 원본 위치에 변환 출력을 만들지 않고 검증된 산출물만 요청한 목적지에 반영한다.

## 과학적 검토

제목–근거–해석의 대응, 비교 조건·단위·기준값, 출처, 불확실성·대안 해석과 계산 상태를 확인한다. 여러 결과를 합치면 같은 계산·시료인지 식별한다. 빠진 자료를 추정으로 채우지 않는다. 발췌만 제공되면 검토 범위도 한정한다.

랩미팅은 새 사실·미해결 문제·필요 결정·다음 검증이 드러나는지, 학회·세미나는 연구 질문에 결과가 답하는지, 학위심사는 기여와 타당성의 근거가 드러나는지 확인한다.

## 파일·시각 검토

아래 `SLIDES_DIR`는 설치된 `slides`, `WORK_DIR`는 작업 전용 디렉터리다. `python`은 의존성이 준비된 작업 전용 환경을 사용한다. 실제 호출 전에 경로를 확정한다.

```bash
python "$SLIDES_DIR/scripts/render_slides.py" "$WORK_DIR/deck.pptx" --output_dir "$WORK_DIR/rendered"
python "$SLIDES_DIR/scripts/create_montage.py" --input_dir "$WORK_DIR/rendered" --output_file "$WORK_DIR/montage.png"
python "$SLIDES_DIR/scripts/slides_test.py" "$WORK_DIR/deck.pptx"
python "$SLIDES_DIR/scripts/detect_font.py" "$WORK_DIR/deck.pptx" --json
```

- 생성 소스에 `warnIfSlideHasOverlaps`와 `warnIfSlideElementsOutOfBounds`를 포함하고 의도한 겹침은 근처 코드에 이유를 남긴다. 자동 경고와 실제 결함을 구별한다.
- 고정 버전 `slides_test.py`는 넘침 시 `ERROR:`를 출력해도 종료 코드가 0일 수 있다. 실패 메시지·문제 슬라이드까지 확인한다. 통과 출력도 상자 내부 텍스트 잘림이나 과학적 정확성을 보장하지 않는다.
- `render_slides.py`는 임시 PDF를 삭제하고 PNG만 남긴다. 납품용 PDF는 별도 출력 디렉터리에 만든다. LibreOffice는 작업별 임시 user profile과 명시적 출력 디렉터리로 호출한다.
- render·raster 변환·montage의 기본 출력은 입력 근처일 수 있다. 독립 입력 사본과 명시적 출력 경로를 사용하고 새 렌더 디렉터리로 기존 결과 혼입을 피한다.
- 모든 장의 렌더를 직접 확인한다. 제목·본문·축·범례·출처의 잘림, 겹침, 대비·여백, 색·기호와 미완성 placeholder를 확인한다. montage만으로 세부 검토를 대신하지 않는다.
- 수정한 장을 다시 렌더링하고 다른 장에 영향이 있으면 함께 확인한다. 오류가 해결되면 근거 없이 검사를 반복하지 않는다.
- PPTX의 텍스트·노트·슬라이드 순서·자산 연결을 확인한다. LibreOffice 렌더·XML 검사와 실제 Microsoft PowerPoint 열기 검증을 구분한다.

## 전달

요청에 맞춰 PPTX, 생성 `.js`, 재생성에 필요한 helper·입력 자산·패키지 정보, PDF와 미리보기를 제공한다. 전체 장을 이미지로만 넣은 파일을 편집 가능한 PPT라고 부르지 않는다. 수행한 과학적·파일·시각 검토와 미수행 항목을 구분해 보고한다. 읽지 못한 파일·실패한 렌더·해결 못한 글꼴 문제를 숨기지 않는다.
