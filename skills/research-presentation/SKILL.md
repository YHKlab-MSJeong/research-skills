# 연구 발표 PPT

청중이 연구 질문, 근거, 해석과 한계를 따라가고 발표 목적에 맞는 판단을 할 수 있도록 구성한다. 전달을 개선하면서 결과나 논증의 공백을 만들어 채우지 않는다.

## 요청과 발표 유형부터 파악하기

- 기존 요청·자료·발표에서 유형, 청중의 지식, 발표 시간과 질의 시간, 전달 목적, 언어, 원본·템플릿, 수정 범위와 산출물을 확인한다. 결과·범위·비용을 실질적으로 바꾸는 누락만 질문하고 나머지는 가정을 밝히고 진행한다.
- 아래 유형을 먼저 선택한다. 명확한 랩미팅을 학회 발표 구조로 다시 묻지 않는다. 혼합 발표는 주된 목적을 기준으로 필요한 부분을 결합한다.

| 유형 | 발표를 통해 달성할 일 | 구성의 중심 |
|---|---|---|
| 학회·세미나 | 연구의 결과와 의미를 이해·평가하게 하기 | 연구 질문 → 기존 연구의 한계 → 접근법 → 핵심 결과와 근거 → 의미와 한계 |
| 랩미팅·진행 보고 | 진행 상황을 공유하고 문제 해결·다음 결정을 돕기 | 현재 목표·지난 결정 → 새 사실 → 실패·미해결 문제 → 가능한 해석 → 선택지와 다음 검증 |
| 학위심사 | 독창적 기여와 연구의 타당성을 평가받기 | 질문과 기여 → 방법의 타당성 → 결과와 검증 → 한계와 기여 정리 |

- 전체 구성·새 발표에는 [유형별 작성 가이드](references/presentation-guide.md)를 읽는다. 파일 제작에는 [제작·검토 절차](references/production-review.md)를 읽는다. 근거 설명이나 규칙의 적용 한계가 필요하면 [출처와 근거](references/sources.md)를 읽는다. 모든 참조를 매번 읽지 않는다.
- 한 장 수정이나 제목 교정에는 해당 범위만 적용한다. 전체 재구성, 새 분석, 매 단계 승인을 강제하지 않는다. 기본 설명은 한국어로 하고 슬라이드 언어는 요청을 따른다. 지정이 없으면 제공된 발표 자료의 언어를 유지한다.

## 주장과 근거를 보존하기

- 관측·계산 결과, 해석, 가설, 향후 계획을 구분한다. 미수렴·진행 중·미검증 계산을 완료된 물리적 결과로 쓰지 않는다. 정적 검사, 계산 정상 종료, 수렴, 모델 타당성은 서로 다른 근거다.
- 수치·단위·부호·비교 기준·조건·표본 수·불확실성·에너지 기준·식과 기호·출처를 임의로 바꾸지 않는다. 없는 결과·문헌·유의성·인과성·신규성을 만들지 않는다. 필요한 부분은 `[확인 필요: …]`로 표시한다.
- 제목과 결론은 실제 근거의 강도에 맞춘다. 불일치·음성 결과·대안 해석을 숨겨 이야기를 완성하지 않는다. 특히 랩미팅에서는 미해결 문제를 질문형 제목으로 남길 수 있다.
- 출처는 해당 그림·주장이 나오는 슬라이드에 일관되게 표시한다. 발표 작성법 자료를 연구 결과의 과학적 근거로 자동 인용하지 않는다. 검색하지 않은 문헌을 확인했다고 말하지 않는다.
- 원본 연구 데이터·계산 출력·기존 발표는 입력으로 보존한다. 새 파일을 만들거나 명시적으로 요청한 편집 범위만 변경한다. 발표 제작 요청 자체는 계산 실행·제출이나 외부 공개를 승인하지 않는다.

## 슬라이드 설계

1. 발표가 남겨야 할 메시지 또는 논의할 결정을 정하고, 이를 뒷받침하는 근거와 필요한 배경을 연결한다. 주장에 맞춰 데이터를 선택하거나 바꾸지 않는다.
2. 새 발표에서는 슬라이드별 `목적 | 제목 | 근거 그림·데이터와 출처 | 핵심 설명·전환 | 예상 시간`을 정리한다. 누락된 근거는 명시한다. 좁은 수정마다 이 표를 별도 제출물로 요구하지 않는다.
3. 한 장에 중심 목적 하나를 두고 제목과 본문을 연결한다. 결과는 문장형 메시지, 미해결 문제는 명확한 질문을 우선한다. 비교에 필요한 여러 패널은 같은 장에 둘 수 있다.
4. 설명하는 그림·그래프를 크게 배치하고 핵심 영역을 표시한다. 논문 패널을 그대로 축소하지 않는다. 장식용 이미지나 아이콘을 모든 장에 강제하지 않는다. 그림·수식의 글자와 단위도 읽혀야 한다.
5. 긴 문단은 필요한 핵심 문장·라벨로 줄이고 세부 조건·유도·추가 결과는 발표 노트나 보조 슬라이드에 둔다. 결론을 평가하는 데 필수적인 조건·한계를 뒤로 숨기지 않는다.
6. 리허설에서 실제 설명 시간과 장 사이의 연결을 확인한다. ‘한 장당 1분’, ‘6단어×7줄’, ‘18pt’, 고정 슬라이드 수는 보편적 합격 기준이 아니다. 숫자는 청중·장소·내용에 맞춰 쓰는 출발점이다.

## 실제 PPT 제작과 검토

- `.pptx` 생성·편집을 요청하면 먼저 [제작·검토 절차](references/production-review.md)를 읽고, 설치된 별도 `slides`의 `SKILL.md`를 읽어 제작한다. 일반 위치는 이 스킬의 형제 디렉터리 `../slides/SKILL.md`다. 내용 구성·검토만 요청하면 제작 도구를 실행하지 않는다.
- `slides`가 없거나 의존성이 실행되지 않으면 그 상태를 밝힌다. 구성·원고 등 가능한 부분은 완료하되 파일 제작이나 검증이 끝났다고 말하지 않는다. 다른 외부 서비스로 조용히 전환하지 않는다.
- 기본 새 발표는 16:9, 기존 발표는 기존 비율·템플릿·스타일을 따른다. 글꼴은 한글과 수식의 실제 렌더링까지 확인한다. 가독성이 떨어지면 글자를 계속 줄이기보다 내용을 나누거나 배치를 바꾼다.
- 검증된 과학 그림을 우선 보존하고 텍스트·단순 도형은 가능한 한 편집 가능하게 만든다. 그림의 편집 가능성보다 수치·축·단위·기준값의 정확성을 우선한다.
- 과학적 검토와 파일·시각 검토를 별도로 한다. 구조 검사가 통과해도 모든 슬라이드의 렌더링을 확인한다. 실제 PowerPoint에서 열어 보지 않았다면 그 호환성 검증까지 완료했다고 말하지 않는다.

## 마무리

요청한 구성·수정문·파일을 먼저 제공한다. 중요한 변경 이유, 검증한 범위와 해결하지 못한 항목을 짧게 덧붙인다. 전체 제작에는 PPTX, 생성 소스와 재생성에 필요한 자산, PDF와 슬라이드 미리보기를 제공한다. 특정 형식만 요청하면 그 요청을 따른다.
